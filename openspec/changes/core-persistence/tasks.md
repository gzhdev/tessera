# core-persistence · 任务

> 第 2 组要一次做完设计书 §11.2 的**全部**六张表，包括本 change 下游尚未用到的。理由见 design.md 的 Risks 第一行——`001_init.sql` 一旦发布就改不回去，结构越晚定型代价越高。

## 1. 连接与迁移基础设施

- [ ] 1.1 引入 `rusqlite`（`bundled` 特性）与 `r2d2` / `r2d2_sqlite`，建立连接池，开启 WAL、外键约束、`synchronous = NORMAL`。验证：并发测试中一个写事务进行时其他线程的读能正常完成，不被阻塞
- [ ] 1.2 实现迁移器：`migrations/{NNN}_{name}.sql` 经 `include_str!` 嵌入，启动时读 `schema_migrations` 最大版本并按序应用未应用的脚本，每条在单事务内完成。验证：重复启动时已应用的迁移不再执行；故意让某条迁移中途失败，断言该条改动被完整回滚
- [ ] 1.3 实现迁移前的自动备份，产出带版本标识的备份文件。验证：存在未应用迁移时执行前生成备份文件，且备份内容与迁移前的数据库一致
- [ ] 1.4 实现降级保护：数据库版本高于代码支持的最高版本时拒绝启动并给出可操作提示。验证：手工把 `schema_migrations` 版本改高后启动被拒绝，且数据库内容未被修改
- [ ] 1.5 实现开发模式专用的「重建数据库」入口，与正常启动的迁移路径分离（design.md D4）。验证：该入口在非开发模式下不可达；`001_init.sql` 文件顶部写明「已冻结，结构变更请新增迁移」

## 2. 表结构

> 对应 `specs/persistence/spec.md`

- [ ] 2.1 在 `001_init.sql` 中建立 `schema_migrations` 与 `plugins` 表。验证：首次启动后两表存在，字段与设计书 §11.2 一致
- [ ] 2.2 建立 `plugin_permissions`、`plugin_config`、`plugin_storage` 三表，均以外键从属于 `plugins` 并设 `ON DELETE CASCADE`。验证：删除一条 `plugins` 记录后，这三张表中该插件的行全部消失，无孤儿行
- [ ] 2.3 建立 `virtual_dirs` 与 `host_settings` 表。验证：两表存在且字段与 §11.2 一致
- [ ] 2.4 在 `001_init.sql` 中插入三个内置虚拟目录别名（`plugin-data` / `workspace` / `temp`）并标记 `builtin = 1`（design.md D7）。验证：首次启动后三条记录存在且 `builtin` 为真
- [ ] 2.5 为 `plugins` 表增加存储用量计数列（字节数与键数量），供第 4 组使用。验证：新建插件记录时两列初始为 0

## 3. 表访问层

- [ ] 3.1 实现 `plugins` 表的访问层：登记、查询、启用停用、更新最后激活时间、卸载。验证：单元测试覆盖增删改查，卸载时级联清除生效
- [ ] 3.2 实现 `plugin_permissions` 与 `virtual_dirs` 的访问层，含内置别名的删除保护。验证：尝试删除 `builtin = 1` 的别名被拒绝；删除用户自建别名成功
- [ ] 3.3 实现 `plugin_config` 与 `host_settings` 的访问层（仅存取，不含 schema 校验——那属 `core-host-config`）。验证：单元测试覆盖读写与覆盖写
- [ ] 3.4 验证配置值与私有数据的分离：两类数据存放于不同表，互不干扰。验证：写入大量私有数据后，该插件配置值的读取结果不变

## 4. 配额与保留命名空间

> 对应 `specs/storage-quota/spec.md`

- [ ] 4.1 实现 `plugin_storage` 的插件侧写入接口，与计数器更新放在同一事务内（design.md D5）。验证：写入后计数列与实际 `SUM(length(value))` 一致；覆盖写入按差值更新
- [ ] 4.2 实现三重配额检查（总量 16 MB / 键数 10000 / 单值 1 MB），超限拒绝写入且不破坏已有数据。验证：三条各有一个边界用例，超限时返回配额超限错误且已有数据完好
- [ ] 4.3 验证配额按插件独立。验证：插件 A 用满配额后，插件 B 的写入仍然成功
- [ ] 4.4 实现 `__` 前缀拒写：插件侧接口拒绝该前缀的键，返回参数非法错误。验证：写 `__picked/abc` 被拒；写 `_internal` 与 `cache__data` 正常
- [ ] 4.5 实现宿主侧的保留键写入接口（与插件侧分为两个函数，design.md D6），且不更新配额计数器。验证：宿主写入 30 MB 内容后，该插件自身可用配额不变，仍能正常写自己的数据
- [ ] 4.6 实现交付条目的独立上限：单条不超过单次文件读取上限，同时存活不超过 4 条，超出淘汰最旧。验证：写入第 5 条时最旧一条消失，新条目写入成功
- [ ] 4.7 实现插件停用时清除其全部 `__picked/*`，且不设时间过期。验证：停用后交付条目消失而普通键值数据保留；写入后经过很长时间仍可读取
- [ ] 4.8 实现用量查询（不含保留命名空间）与手动清理（清理时顺带重算计数器）。验证：查询结果不含保留命名空间占用；清理后用量归零且可重新写入

## 5. 集成验证

- [ ] 5.1 端到端：从无数据库文件开始启动，建库、应用迁移、插入内置别名、登记一个插件、写读配置与私有数据、卸载插件。验证：全流程无错误，卸载后无残留行
- [ ] 5.2 跨重启验证：写入数据后重启，数据完整且迁移不重复执行。验证：重启前后数据一致，`schema_migrations` 未新增记录
