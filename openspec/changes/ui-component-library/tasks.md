# ui-component-library · 任务

> 按 design.md D7 分两批：第 1–4 组是第一批（分发器 + 6 个组件 + 全部机制 + 测试基建），第 5 组是第二批（批量补齐约 24 个组件）。第一批结束时应能演示完整回路，机制问题在那时暴露而不是在第 30 个组件写完之后。

## 1. 测试基建与 fixture 体系

- [x] 1.1 搭建前端测试环境（Vitest + Vue Test Utils 或等价）。验证：一个平凡组件的渲染测试能跑通
- [x] 1.2 建立 `src/components/ui/__fixtures__/` 并放入第一批所需样例：全组件覆盖树、三层嵌套容器树、含未知类型的树、含重复 id 的树。验证：每份 fixture 都能被测试加载并通过生成的 TS 类型检查
- [x] 1.3 建立 fixture 驱动的测试骨架：加载 JSON → 渲染 → 断言。验证：骨架能对 1.2 中任一 fixture 跑通

## 2. 渲染器骨架

> 对应 `specs/ui-renderer/spec.md` 的分发与降级 Requirement

- [x] 2.1 实现 `<UiNode>`：读取节点 `type`，从映射表取组件并动态渲染（design.md D1）。验证：映射表的键与生成的 TS 联合类型对齐，遗漏某组件类型时 `tsc` 报错
- [x] 2.2 实现容器组件内部的递归渲染（递归点由容器自己决定，不在 `<UiNode>` 内）。验证：三层嵌套 fixture 的层级与顺序与描述树一致
- [x] 2.3 实现非容器组件忽略 `children`。验证：为非容器节点附加 `children` 时不产生额外输出
- [x] 2.4 实现未知类型降级：映射表未命中即渲染错误占位符并记警告（design.md D2，不在前端重跑 schema 校验）。验证：10 节点含 1 未知的 fixture 中，9 个正常渲染，第 10 个显示占位符，警告含未识别的类型名
- [x] 2.5 确认占位符内容可被用户理解，不留空也不显示原始 JSON。验证：快照测试断言占位符含说明性文字

## 3. 重绘语义与事件

- [x] 3.1 以节点 `id` 作为渲染比对依据。验证：重绘前后 `id` 未变的输入框保持焦点；`id` 未变的列表保持滚动位置
- [x] 3.2 实现同树内重复 `id` 的警告，含重复值与位置。验证：重复 id fixture 触发可定位的警告
- [x] 3.3 实现交互打包为 `{ nodeId, event, action, value }` 并抛给可注入的 handler（不接 IPC）。验证：点击按钮时 handler 收到的 `action` 恰为节点 `on` 中声明的字符串
- [x] 3.4 实现「未声明的事件不上报」。验证：点击 `on` 中无 `click` 项的按钮时 handler 未被调用

## 4. 输入模型与第一批组件

> 对应 `specs/ui-input-model/spec.md`

- [x] 4.1 实现 `vstack`、`hstack`、`text`、`button` 四个组件。验证：各自的 fixture 渲染结果符合快照；button 的点击按 3.3 上报
- [x] 4.2 实现 `text-input` 的本地态优先模型（design.md D3）：聚焦且未声明强制取值时用本地值，否则用新树的值并同步本地值。验证：用户输入过程中推送含不同值的新树，输入框保留用户内容且光标不动；未聚焦时推送新值则显示新值
- [x] 4.3 实现文本类输入的上报时机：仅在失焦或回车时上报。验证：键入 10 个字符期间零上报；失焦与回车各触发一次，携带完整内容
- [x] 4.4 实现 `props.forceValue` 逃生舱。验证：新树声明强制取值时，即便处于聚焦状态内容也被替换
- [x] 4.5 实现 `props.debounce` 节流，实现在组件内部（design.md D4）。验证：声明 300ms 后连续键入 2 秒，上报次数不超过按间隔计算的上限；未声明时输入过程中零上报
- [x] 4.6 实现 `table` 组件与行点击事件。验证：行点击时 `value` 同时携带行序号与该行数据
- [x] 4.7 实现输入类组件的禁用状态。验证：禁用的按钮点击不产生上报；新树把禁用改为可用后重新响应交互
- [x] 4.8 **第一批验收**：用 fixture 完整演示「渲染 → 交互 → 收到事件 → 推送新树 → 输入不被破坏」的回路。验证：该演示可在无插件、无沙箱、无 IPC 的条件下跑通

## 5. 批量补齐组件

- [x] 5.1 补齐布局类：`grid`、`scroll`、`tabs`、`group`、`spacer`、`split`。验证：各有 fixture 与快照测试
- [x] 5.2 补齐展示类（不含 markdown/code）：`heading`、`badge`、`divider`、`icon`、`image`、`empty-state`。验证：同上；`image` 能渲染内联数据形式的来源
- [x] 5.3 补齐输入类：`textarea`、`number-input`、`select`、`checkbox`、`radio-group`、`switch`、`slider`。验证：即时型控件（开关、复选框、单选组、下拉）值变化时立即上报，不等失焦；`textarea` 沿用 4.2 的本地态模型；`slider` 按 design.md Risks 第三行处理为「交互进行中」而非严格聚焦
- [x] 5.4 补齐数据类与反馈类：`list`、`tree`、`key-value`、`alert`、`progress`、`spinner`。验证：各有 fixture 与快照测试
- [x] 5.5 实现 `file-picker`：选定后向上抛出含 `{ token, fileName, size }` 的事件。验证：事件载荷不含任何路径字段

## 6. 富文本与代码组件

> 单列一组：这两个组件涉及库选型与安全约束，与其余组件的性质不同

- [x] 6.1 选定 markdown 解析库，要求默认转义 HTML 且支持子集裁剪（design.md D6）。验证：测量并记录该库对前端产物体积的增量；若候选库默认解释 HTML 则换库而非加配置
- [x] 6.2 实现 `markdown` 组件，限定为受限子集（标题、列表、表格、代码块、链接、强调）。验证：含 `<script>` 的内容以字面文本显示，不被解释为标记
- [x] 6.3 实现链接点击拦截，交由宿主决定处理方式。验证：点击外部链接时页面不跳转，而是触发拦截回调
- [x] 6.4 选定并实现 `code` 组件的语法高亮，语言按需加载。验证：记录体积增量；仅加载 fixture 中实际用到的语言

## 7. 收尾验证

- [x] 7.1 补齐剩余 fixture：大表格（几百行）、含 HTML 注入的 markdown 树。验证：每条 spec 场景至少对应一个 fixture
- [x] 7.2 测量大表格 fixture 的渲染表现。验证：记录结果；若明显卡顿，虚拟滚动作为 `table` 内部优化另行处理，不改契约
- [x] 7.3 确认整个 change 期间未在前端本地修补过生成的类型。验证：`src/types/generated/` 的一致性检查全绿；期间发生的契约调整都能追溯到 `ui-schema-and-typegen` 的对应改动
